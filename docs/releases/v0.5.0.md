# Local Model Gateway v0.5.0 (Unreleased)

Version 0.5.0 is an unreleased release candidate. It adds an experimental
managed music path and tightens request accounting, runtime operations, and
dependency maintenance across the gateway.

## Highlights

- Added managed `POST /v1/audio/speech` routing through the existing GPU queue.
  The route requires a managed runtime with `supports_audio: true`, non-blank
  `input` and `instructions`, and currently supports non-streaming WAV output.
- Added the experimental MiniMax Music 3 adapter for Apple Silicon/MPS. Each
  request uses one native generation pass with a preallocated language-model KV
  cache. `audio_duration` sets the maximum target duration; a lower
  `min_audio_duration` allows an earlier model-selected ending.
- Extended the managed proxy timeout to response headers and body transfer so
  long audio responses can use the runtime's configured timeout.
- Preserved the first terminal request outcome in history and telemetry. A
  late upstream callback cannot turn completed, failed, or cancelled work into
  another state.
- Aborted or timed-out upstream response bodies now release GPU admission even
  when the response is never read.
- Active prefill telemetry now requires fresh progress from the current
  request, so an earlier request cannot appear as current work.
- Added service-install preflight for the exact Node executable and gateway
  entrypoint before an existing macOS launchd service is replaced.
- Updated the macOS llama-server adapter for modern and legacy slot telemetry,
  atomic progress writes, generation-aware prefill reporting, quoted
  environment paths, and empty extra-argument lists.
- Added XML escaping and temporary-plist linting to the MiniMax launchd
  adapter, and updated MiniMax validation for blank audio fields, invalid
  numeric/integer values, non-positive inference steps, and out-of-range seeds.
- Updated the dependency lockfile for security remediation.

## Audio request contract

The gateway routes each request to an audio-capable managed runtime. This
experimental endpoint accepts lyrics and style instructions and returns binary
WAV data; clients using an OpenAI-compatible library must send the required
`input` and `instructions` fields.

Every request must include:

- `model`: a configured managed runtime alias with `supports_audio: true`
- `input`: non-blank lyrics or text
- `instructions`: non-blank musical style or production direction

The current route accepts `response_format: "wav"` and `stream: false` only.
Runtime-specific values such as `seed`, `max_new_tokens`, `audio_duration`,
`min_audio_duration`, and `num_inference_steps` are passed to the selected
runtime. The response is binary WAV data.

See [Music Generation](../music-generation.md) for the request shape and
[MiniMax Music 3 Runtime](../../examples/runtime-adapters/minimax-music3/README.md)
for the experimental adapter setup.

## Upgrade

Use Node.js 22. From a source checkout:

```bash
git pull --ff-only
npm install
npm run build
npx local-model-gateway doctor --json
```

If `doctor --json` returns top-level `status: fail`, inspect and follow the
read-only plan printed by:

```bash
npx local-model-gateway doctor --fix-plan
```

If you already installed the experimental MiniMax adapter by copying files into
`runtime/`, refresh the copied files from
`examples/runtime-adapters/minimax-music3/` before restarting it. This includes
the updated `server.py`, the new `request_validation.py`, the helper modules,
`requirements.txt`, and the service script. The repository does not synchronize
ignored runtime files automatically.

Updating the checkout and running the doctor do not restart the gateway or its
runtimes. Restart them explicitly when the local installation is ready. On
macOS, `local-model-gateway service install` performs its own runtime preflight
before replacing the launchd service.

Only set `supports_audio: true` for a managed runtime that implements the
contract above. Existing text runtimes default to `false` and continue to
serve their existing routes.

## Verification status

Automated verification for this candidate covers the TypeScript build and
typecheck, Node tests, coverage, dependency audit, public safety scan, package
dry run, local visual checks, and the lightweight MiniMax adapter validation
tests. The review did not perform a fresh model-load or GPU-generation smoke
test, so the experimental audio runtime still needs a real request on the
target Apple Silicon/MPS machine before this candidate is tagged or published.

## Known limitation

When a client disconnects, the gateway closes the request and records the
cancellation. The current MiniMax adapter performs generation synchronously and
may finish its current native pass before handling another request; cancellation
does not guarantee an immediate interruption of GPU computation.

This candidate is not tagged or published.
